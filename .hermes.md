# BerryListings — Backend API

A REST API for managing real estate property listings under the "Berry" brand.

## Stack
- Node.js 20+ ESM (`"type": "module"`)
- Express 4.x
- MySQL via Prisma ORM 5.x
- Google OAuth + JWT auth (`google-auth-library`, `jsonwebtoken`)
- Swagger/OpenAPI at `/docs`
- Vitest + Supertest for testing
- ESLint + Prettier + Husky pre-commit hooks

## Commands
```bash
npm test              # Vitest (unit + integration via supertest)
npm run dev           # nodemon for local dev
npm start             # production start
npm run lint          # ESLint check
npm run lint:fix      # ESLint auto-fix
npm run format        # Prettier format
npm run format:check  # Prettier check
npm run db:seed       # Seed admin user from ADMIN_USER env var
npx prisma migrate dev  # Run migrations
```

## Build & Run
```bash
docker compose up --build   # local dev (app + MySQL)
docker build -t berrylistings . && docker run -p 3000:3000 --env-file .env berrylistings  # production
```

## Important Conventions
- NEVER send `agentId` in property create/update requests — the API derives ownership from the authenticated user
- `photos` array order = display order; omitting preserves existing, empty array removes all
- Property types: HOUSE, CONDO, TOWNHOME, LAND
- Property statuses: DRAFT, ACTIVE, PENDING, SOLD
- Admin-only routes: all `/api/v1/users` endpoints require admin role + isEnabled
- Login: POST `/api/v1/auth/google` with Google ID token → server verifies, checks User table, issues JWT
- Seeds: `ADMIN_USER` env var seeds the first admin via `db:seed`; `ADMIN_PASS` is unused (no password auth)

## Testing
